# 路线图：从"智联专用"走向"多平台通用"

## 阶段一：抽适配层（当前最急）

目标：把站点差异收敛到一个目录，业务层不再出现具体选择器。

```
src/engine/sites/
  index.js        注册表：按域名选 adapter
  zhaopin.js      智联（把现有 scraper/automation 迁进来）
  boss.js         BOSS 直聘（待做）
  job51.js        前程无忧 51job（待做）
  liepin.js       猎聘（待做）
  _shared.js      通用工具：等待节点、滚动、文本清洗、频率控制
```

统一接口（草案）：

```js
{
  id: 'zhaopin',
  match(url),                       // 是否归我管
  async ensureLogin(wc),            // 判断登录态，必要时提示人工
  async searchJobs(wc, query),      // 返回岗位卡片数组
  async readJob(wc, job),           // 打开详情，补全 JD 正文
  async apply(wc, job),             // 投递，返回 {ok, reason}
  async listThreads(wc),            // 会话列表
  async readThread(wc, thread),     // 最近消息 [{isMine, text}]
  async sendReply(wc, thread, text) // 发送
  selectors                          // 自检用：关键节点清单
}
```

## 阶段二：选择器自检与自愈

- 启动或切换页面时跑 `selectors` 自检：核心节点缺失 → 面板报警 + 暂停自动动作，而不是静默跳过。
- 选择器写成"多候选"数组（新老结构都列上），命中第一个可用的。
- 记录每个站点的成功/失败次数，连续失败自动降级为"只出稿不发送"。

## 阶段三：模型调度层

- 统一封装：并发池、超时、429 退避、JSON 校验重试、响应结构修复。
- 支持本地模型（Ollama / llama.cpp / vLLM）做离线兜底，断网也能跑规则链路。
- 精排支持"后台队列"：投递先用规则分，模型分算完再回填并更新面板。

## 阶段四：站点扩展顺序（按投入产出）

1. **BOSS 直聘**：岗位量最大，IM 交互最重，适合先做。
2. **前程无忧 51job**：老牌站，表单投递多，适配成本中等。
3. **猎聘**：中高端岗位，对"销售总监/区域负责人"这类画像更友好。
4. **拉勾**：互联网岗位为主，可作为补充。
5. **脉脉 / 领英**：社交推荐流，结构差异大，放在后面。
6. **智联招聘**：已有实现，持续维护选择器。

## 阶段五：体验

- 投递漏斗：搜索量 → 精排 → 投递 → 回复 → 面试邀约，按天可视化。
- 简历对比视图：原文/优化版并排 diff，改动逐条可接受/拒绝。
- HR 心理分析结果可视化：这条消息判成什么意图、潜台词是什么、为什么这么回。

## 明确不做

- 不做多账号批量养号、不做绕过平台风控、不做伪造经历。
- 不做"一键海投骚扰"——投递上限和过滤规则是刻意保留的。
